## 补充：运行一段时间后从 5 变回 2

用户澄清不是单纯刷新恢复。本次在 `fix/v0.0.19-context-delayed-reset` 继续排查，修改前基线 `5d5f09f`，没有重复修改产品逻辑；下述运行时复现证明前轮移除的省 token 回写确实会导致这个延迟症状。

在改前 `7fa55f2` 的完整页面中，关闭记忆自动总结与替换、开启省 token，使用真实输入事件把全文章数从 2 改为 5，按顺序操作：

1. 输入并失焦、等待原保存流程完成：界面值、运行值、IndexedDB 均为 5。
2. 空闲 10 秒，再关闭并重新打开全局设置：仍为 5，没有刷新页面。
3. 发起下一次正文生成：生成准备阶段运行值从 5 变为 2，生成完成再打开设置，输入框和 IndexedDB 均为 2。

隔离页同步跟踪记录到约第 15.9 秒发生写入，调用栈为 `startGeneration → doGenerateOne → buildChapterMessages → normalizeContextSettings`；触发语句正是旧版 `Math.min(Number(settings.value.contextFullChapters) || 1, 2)`。它不是等待到某个固定时间触发，而是用户填写后，下一次准备正文请求时触发。已有记忆、书稿和模型响应没有改写这个设置。

前轮修复已将省 token 的 2 章限制留在请求组装的局部变量中，不再写回保存值。用户填 5 时省 token 开启仍实际带最多 2 章；关闭省 token 后恢复按保存的 5 章选择原文，仍受字数预算约束。旧版已经改小并保存的数值不能猜测还原。

新增 `scripts/v19-context-chapter-lifecycle-browser.cjs`，复用原隔离浏览器入口，已接在 `--chapter-settings` 后，因此既有 `gate:browser` 会自动运行。本次同步跟踪只存在于测试页，不给产品新增守护监听、定时恢复、存储字段或键。

## 结论与原因

未取得反馈者当前存档与模型请求，不能判定其个人故障的唯一原因。通过执行现有函数和隔离浏览器，确认以下独立问题：

| 位置 | 改前行为 | 修复 |
| --- | --- | --- |
| normalizeContextSettings | 省 token 开启时直接改写章数、摘要数及五个字数上限；如 8 章刷新为 2，关闭模式也无法恢复原值 | 只补缺省、校正非法章数；请求限制不回写保存值 |
| 章数输入 | 依赖 change 失焦与 2 秒防抖，手机未失焦／快速刷新存在未及时落库窗口 | input 立即复用原保存队列、重试与失败提示；没有新存储路径 |
| buildBudgetedChapterHistory | 开启记忆时忽略全文章数，改读 summaryKeepChapters；只读记忆也会把作者选的 8 章变成 2 章 | 默认只读记忆遵守全局章数；主动开启替换时，同时受全局章数与记忆保留数限制 |
| 数字兜底 | 0 被 || 当成缺省，普通模式仍发 3 章 | 0 为有效选择，所有记忆／省 token 组合均不发原文 |
| 同一前文组装函数 | 最新长章碰到单章上限就停止读取更早原文，即使总预算充足；记忆开启还会绕过单章上限 | 一章达到单章上限后，剩余预算继续分给更早章节；记忆开关不再绕过字数设置 |
| buildChapterMessages | 先组装前文，再校正设置，首轮和下一轮可能不同 | 先校正设置，再组装系统与前文，预览／实际发送保持一致 |

输入框说明改为“原文数量上限”，标明字数预算仍生效、0 的含义、省 token 最多 2 章及主动记忆替换的限制。记忆库旁的说明同步澄清。全文章数和摘要章数输入均为 44px、保留原 v-model；已有设置值不迁移、不猜测还原。

默认前文字数预算仍是 15,000，单章默认上限仍是 5,000，默认全文章数仍是 3。三至四章之前细节变少也可能是预算的正常结果：例如每章约 5,000 字，15,000 字预算只能带约三章原文。更早或被截短部分继续使用已有章节摘要、有效记忆和长期总结，不自动生成或改写它们；缺摘要沿用合并章号提示。卷纲、当前细纲、卷末交接不计入此原文预算。

## 边界与后续

在上述覆盖范围内未发现前文发送、保存刷新、分支及旧记忆回归问题。本轮没有复现反馈者原书，也没有验证真实模型是否遵守、服务商上下文上限或 iOS／厂商手机浏览器；实际模型仍可能忽略已发送内容，不能仅凭模型回答判断存档丢失。

之前已被旧代码改小并保存的数字无法可靠推回原值，用户需重新设置一次。摘要章数的现有策略未重做：预算外章节继续用可用摘要／记忆补足，不按该数字硬删除旧事实。本轮未重复完整 gate:browser 或线上 gate:release，只重跑表中受影响浏览器专项；后续上传仍需用户授权及公测流程。
