# v0.0.19 GLM 文本卷纲解析复验报告

日期：2026-11-15。修改位置为主目录 `Moyun`，分支 `v0.0.19/L1-foundation`。本轮只修复解析和回归验证，不发布、不上线。

## 问题与原因

真实输入 `F:\yydcm129\素材\GLM5.3flash测试文本.txt` 的 `【卷纲规划】` 部分明确包含 4 卷：1–10、11–20、21–30、31–40。底层 `parseVolumePlan` 原本已经能读出 4 卷，但大纲生成入口先调用 `normalizeOutlinePlanningPayload`，该入口只扫描 JSON/结构化片段。文本格式因此返回 `null`，后续请求没有得到 4 卷候选。

## 修复

- `normalizeOutlinePlanningPayload` 在没有结构化卷数据时复用 `parseVolumePlan`，把文本卷纲转换为统一的 `number/title/startChapter/endChapter/summary/writingRequirement/bridge` 字段。
- 非 JSON 规划保留完整原文作为审阅候选，章节明细、写作要求和衔接点不会只剩摘要行。
- 混合“大纲/细纲/卷纲”分区继续使用原有分区提取行为，避免改变旧入口的字段结果。
- `normalizeGeminiOutlinePayload` 仍只是兼容入口，没有按模型名称添加分支。
- 将用户提供的真实文本固定复制到 `scripts/fixtures/v0.0.19/glm53-text-planning-response.txt`，回归不依赖 F 盘文件存在。

改动前已备份：`.ui-check/glm53-parser-before/moyun.single.html`。
