# 重生成快照查看与清理（2026-11-17，本地未上传）

## 用户问题与实际原因

用户全量导入后找不到旧快照，并要求能查看、删除书内 regenSnapshot，提供项目外可导入的测试书。

原界面只展示本机独立历史库中的书籍恢复点。三种数据用途不同：

| 数据 | 内容与入口 | 是否随书籍全量 JSON 备份 |
| --- | --- | --- |
| chapters[].regenSnapshot | 首次生成时的请求，用于“复用首次注入”；本轮接入“快照历史 → 章节重生成快照” | 是 |
| chapters[].versions | 正文旧稿，在章节标题旁用 ‹ › 查看 | 是 |
| NovelSnapshotsV6/snaps | 本机书籍恢复点，在“本机书籍快照”查看 | 否，现有全量书籍导出未打包独立历史库 |

用户提供的约200.7MB匿名备份含311章、167份 regenSnapshot，但 **versions 为0条，独立书籍恢复点也没有打包进文件**。导入没有把这167份请求丢掉；旧界面没有展示它们。它们不是过去正文版本，不能据此还原不存在于备份中的旧稿。

## 实现与范围

- 沿用现有“快照历史”弹窗，新增两个标签页。重生成列表覆盖当前书的全部分支，按分支自己的章序显示来源，不把主线和支线章号混算。
- 支持查看／收起、逐条删除、删除本书全部重生成快照。列表只保存章节引用；详情展开才格式化，一次显示12000字符，能翻到完整末尾，未裁掉原始数据。纯文本插值，不执行请求中的HTML。
- 删除使用现有 openConfirm，列出条数、当前书全部分支范围、不能复用首次注入、恢复旧备份或书籍恢复点可能带回请求等影响。取消不删。
- 只删除章节的 regenSnapshot，不删正文、正文旧稿、摘要、记忆、细纲、卷纲、分支或其他书。本机书籍快照的保存、恢复、删除保留。
- 保存走原有 saveDataNow → 排队／重试 → DB.saveLibrary；失败恢复章节、书架副本和切书再切回后的运行态，并恢复应急备份，不显示清理成功。确认时切书或快照被替换则中止，不删错对象；AI工作或重复保存期间不执行。
- 没有新增 localStorage 键、数据库、书籍字段或自动清理逻辑。保留 v0.0.19 与既有1116公告。

## 已知边界与回滚

本轮没有恢复备份中不存在的正文旧稿，也没有把本机独立书籍恢复点加入全量备份。浏览器清理／换设备后，这部分独立历史仍需原浏览器数据才能恢复，这是目前最大的备份遗漏。

之后新生成章节仍会保存新的首次请求，没有自动保留上限；恢复旧备份或旧书籍快照也会带回旧请求。用户可再次手动清理。删除后不能“复用首次注入”，正常续写和分支重写不依赖已删除的请求。

未覆盖iOS Safari、实体手机、厂商浏览器、强制断电或系统直接杀进程；本轮没有新增AI调用，没有调用真实服务商。不能把本机窗口／触摸模拟表述为真机已经确认。
