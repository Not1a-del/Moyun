## 四、结论 2：全新存档的预设列表为空

实测（全新临时 profile，应用自动建的第一本书）：

```
books = 1, currentBookId = id_1792321996115_hbgv6784
promptPresetCount = 0
预设页签：cardCount = 0，显示「预设 0 条 / 当前没有可见预设条目」
调用 loadBook(当前书) 后：promptPresetCount = 16，页签渲染 14 张卡片
```

根因：

- `initBooks()`（14997）创建首本书时**不写 `promptPresets` 字段**，也不走 `loadBook`；
- `createNewBook()`（15171）显式写 `promptPresets: []`，注释为"loadBook 时按内置默认补齐"；
- 只有 `loadBook`（15264）/ 存档导入（42582）才会调用 `syncBuiltinPromptPresets` 补齐内置全集。

影响：首次安装、未切换过书的用户，看到的是**空的预设区块**，正文请求里也没有「小说续写模式」那套内容。

### 11.6 常见误判（别踩）

- **"旧预设删干净了"≠"把 `presets` 字段删了"**：删字段会破坏旧存档导入（15261 `book.presets = deepClone(presets.value)`）。
- **不要把 `getPresetsForModule` 当死代码直接删**：MOD 可能按名引用，删了会在 MOD 场景抛错。
- **首装空列表不是 `createNewBook` 的锅**：它显式写 `promptPresets: []` 是**正确**的（等 `loadBook` 补齐），错的是 `initBooks` 没走 `loadBook`。
- **`npm run audit` 只查模板结构**，查不出预设注入问题；反过来，注入问题也不影响 audit 结果。两者不能互相替代。
- **`总字符` 下降不等于功能变好**：先确认 `新预设_*` 仍为 `true`，再比较数字。
- **别把 `hidden` 条目当死数据**：它们会真实注入，只是不在列表显示。
