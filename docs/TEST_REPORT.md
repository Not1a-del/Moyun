## 已知风险与未完成验证

1. 真实 AI API、生图 API、NAI 5 返回图片和超长正文评论生成需要用户配置的在线服务，不能仅凭静态构建判定成功。
2. 本轮 ①③④⑤⑥⑦ 的核心是提示词与格式约束，离线环境只能核验“指令已注入、解析与硬限制可执行”，无法在未发送真实 API 请求（被禁止）的前提下验证模型的实际服从度；建议用户接入真实模型后观察前两章的卷纲回填、补全空白、摘要长度与剧情时间输出。
3. ⑦ 剧情时间链路仅在上一个上下文章节带有合法【...】时间时才要求模型续写本章时间；新书或时间线缺失时不会凭空生成时间，这是有意设计而非遗漏。
4. 摘要 120 字硬截是兜底：若模型持续无视 60-100 字提示词，长摘要会被截断而非报错，用户应关注生成质量而非依赖截断。
5. Tailwind CDN 生产警告仍存在；改为本地构建需要引入依赖，必须单独获得授权。

### v0.0.10 已知风险与未完成验证

1. 流式分段回填（②）在“自动”请求模式下依赖适配器真的走 SSE：若模型端关闭流式或适配器降级为非流式，字段仍会一次性出现（此时与 v0.0.9 行为一致，不会更差）。半截 JSON 抽取已覆盖未闭合引号，但极端截断（字段值中途被适配器重组）可能让某字段先显示不完整值，完成后由整段解析覆盖修正。
2. 卷纲逐章格式（⑤）章行覆盖范围依赖模型服从度：若模型仍偷懒不写章行，宿主回退为旧行为（只回填框架摘要），不会损坏卷数据；但卷摘要会停留在几句话。回归脚本只能验证解析端，无法验证生成端。
3. 细纲比例（⑥）主轮曾用 6% 启发式；补充轮已按用户实测改为 1:4~1:5（中值 ÷4.5，2500 字正文≈556 字/章细纲）。手动改过“细纲字数”的用户仍固定在设置值（改回 3000 恢复自动比例），可能感知不到新比例逻辑。
4. 事件 AI 补充（④）按 3 章一批循环：50 章的书约 17 次请求，每次都是全文正文，token 消耗显著高于旧版单次裁剪请求；中止按钮可随时停止，但用户可能未意识到长书的耗时与成本。请求间失败会导致部分插入（已插入的保留并提示）。
5. 真实 API 行为（流式回调频率、卷纲章行服从度、细纲比例服从度）无法在禁止发送真实请求的前提下验证，建议用户接入真实模型后重点观察前三项。

### v0.0.10 补充轮已知风险与未完成验证

1. 段进度提示（补充③）的“第 X/Y 段”基于已填字段数/批次计数：流式输出中途的计数是近似值（模型可能回头修改前面字段导致计数短暂回跳）；非流式降级时提示会在收到完整文本后一次性跳到末段。进度提示只读已收到的文本，不影响写入逻辑。
2. 全文时间线补充（补充①）的范围弹窗只决定阅读哪些章，事件仍按 3 章一批循环请求，token 消耗与主轮④相同；补充②的 timeText 正确性依赖模型服从度，离线只能验证“提示词已注入、排序逻辑可执行”，无法验证模型实际填得多准。
3. 细纲比例（补充④）的 1:4.5 中值落在用户给的 1:4~1:5 区间内，但模型对“每章细纲≈X 字”的服从度未实测；若用户想要固定 1:4 或 1:5 而非中值，需要下一轮暴露设置项。
4. 全部浏览器验证为离线执行（假 API 配置仅过守卫，无真实请求）；范围弹窗的“开始补充”在验证中未真正发起请求（校验失败即拦截），完整链路（选中范围→逐批生成→插入→排序）建议用户接入真实模型后抽查一次。
