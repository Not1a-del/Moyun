## 结论与修复

检查发现一处实际风险：细纲已按 branchData 分开，但总纲、卷纲和相关规划状态仍留在共享 novel 上。切换分支后，正文可能读取上一条线修改过的总纲或卷纲。MOD 的 system 构造在调用方未明确传入章节时，也会把全书所有分支的正文传给扩展。

现在复用原有 branchData 保存每条线的 outline、volumes、chapterCount、unfinishedMode、unfinishedModeClosed、planReminded、outlineImpact 和 reviewStates；加载、切换和保存都通过同一个规划读取函数处理。书的数据仍跟随 DB.saveLibrary，没有新增 localStorage 键或数据库。

- 新分支继承上级当时的总纲和卷纲副本，此后独立修改；细纲、章节索引等继续执行现有的分叉点截取规则。新分支不继承上级待审和撤销记录，防止误接受旧候选。
- 切换后立即恢复当前线的规划及审阅状态；空大纲和空卷纲也保留为空，不回退到另一条线。
- 分叉复制交接时，只写新分支自己的卷纲容器，不再修改上级卷纲。
- 单独导出支线并提升为主线时，规划、交接和手动整理草稿跟着该线重映射；恢复支线紧急备份时，不把备份中的支线 novel 写进主线规划。
- MOD 默认收到 visibleChapters；正文、摘要、记忆和卷交接继续按当前分支过滤。
- 对尚无独立规划字段的书，从原字段建立副本。旧版只有一份的待审记录只归当时所在分支，不能分发给其他线。

## 场景、输入和方法

环境为 Windows、Node v24.15.0、已有 Edge 157.0.4341.60。全部测试在主目录执行。浏览器 runner 使用临时用户资料和本机 HTTP 页面 http://127.0.0.1:4191/index.html，不使用用户真实书库或 API 凭据。

新增 scripts/v19-branch-context.test.cjs 通过提取生产函数构造数据并断言，包含 6 项：

1. 主线 → 支线 → 孙支线各自修改总纲、卷纲、细纲、待审记录、计划章数和未完状态，反复切换；buildChapterMessages 只含当前线内容，序列化重载仍相同。
2. 前文预算分别走原文、逐章摘要、长期总结、记忆四条路径；交接只读当前线，不能混入主线内容。
3. 只导出孙支线，作为新主线加载后，总纲、卷纲、交接和细纲仍是孙线版本，原数据不变。
4. 原字段初始化为独立副本；空规划不回退；旧待审记录不分发到其他线。
5. 不传 contextChapters 独立调用 buildFullSystemPrompt，MOD 默认只收到当前分支章节。
6. 恢复支线紧急备份后，支线总纲和卷纲更新，主线总纲、卷纲和细纲不变。

消息构造、预算、规划读取等使用生产函数；外部 MOD、预设扩展在单元夹具中用空实现隔离。实际浏览器发送流程另行验证，不能用单元夹具代替页面请求。
