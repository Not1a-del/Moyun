# v0.0.14 修订方案（2026-09-22）

基线：`f8d338c`，回滚分支：`backup/v0.0.14-base-f8d338c`；工作分支：`temp/v0.0.14-work`。

## 范围

1. Gemini 工具回复传输、增量解码、错误识别和全局开关；所有文本 AI 请求入口共用同一传输协议。图片生成、向量接口不适用文本回复工具。
2. AI 结构化结果的保守 JSON 修复、结构校验和明确失败提示。普通导入文件、API 外层响应 JSON 不使用内容修复。
3. 用户选择跳过 NSFW 文本回退，默认提示词和用户自定义均保持原状。
4. 完成 RP-Hub 随机标记机制核对；不实现绕过服务端安全过滤的反标记注入。

## 修订原方案

- 工具只搬运输出，不能恢复模型从未生成或网络从未送达的字符。不承诺永不截断。
- 不把 `length`、`MAX_TOKENS`、过滤、拒绝或未知结束原因改成 `stop`。
- RP-Hub 的 `output_reply` 工具定义、强制工具选择、关闭并行调用、逐字符解码、空回重试至多三次作为兼容基准。真实空回以外的错误不触发该重试。
- 对 `api.sta1n.cn` 保持该请求合同；其他站点不在收到拒绝或过滤后改走另一条通道重试。明确报告不支持的参数，保留用户关闭开关的选择。
- 流式显示必须来自真实接收的分片；非流式服务不能伪装为实时流。
- 开关按实际请求模型判定，未手动指定时 Gemini 自动启用；用户手动开关优先且持久化。
- 保留白鸟现有资料回读与推演显示，不凭猜测禁用两套功能。RP-Hub 检索工具不能未经实现便声明移植完成。
- 补写消息在首轮 messages 之后追加首轮已生成正文和续写要求，保留原消息前缀；缓存命中由服务商决定。
- 原生 Gemini/Anthropic 协议和 OpenAI 兼容协议应分别验证，不能仅凭模型名称套用 OpenAI 工具字段。

## JSON 处理

失败样本正文 7676 字符，原始解析于位置 664 失败；在内存中对 24 个疑似裸引号补转义可解析出 3 个角色。正常样本正文 3011 字符，可直接解析 3 个角色。正常正文有 5 对中文弯引号，旧报告将推理等原始响应计入的统计不能代表正文。证据不能区分模型与中转改写责任。

优先严格解析；随后只做可解释的格式修复；不补造缺失业务字段，不执行返回文本，不以成功解析代替字段校验。错误样本、正常样本、合法转义、Unicode、嵌套对象、歧义和截断均进入回归。修复结果必须可识别，失败不得覆盖既有资料。

## 验收

- 模拟 SSE：逐字节 UTF-8、跨片转义和代理对、缺末尾换行、多行事件、JSON 非流式回退。
- 工具：分片名称/参数、ID 冲突、重复/未知工具、残缺外壳、额外键、非法转义、普通正文与工具避免重复。
- 故障：HTTP 400/401/403/429/500、HTTP 200 内 error、过滤/拒绝、限长、空回、用户取消、断网。
- 请求覆盖：正文、续写、补写、大纲、细纲、一键开书、角色、设定、评论、风格/预设以及 MOD 文本请求。
- 浏览器：桌面、390×844 手机，开关操作/刷新持久化、模型切换、干净空白角色与超长文本卡片宽度≥容器80%。
- 门禁：构建、语法、`npm run audit`、`npm run regress`、新增协议回归、diff review。
- 未执行真实站点付费请求时必须明确说明；模拟通过不能证明某站点当前实现和服务可用。
