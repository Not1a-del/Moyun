# v0.0.19 AI 输入返回保留修复

本轮只处理作者输入在报错、手动返回、关闭入口后重新打开时丢失的问题。近期记忆、摘要替换和正文上下文策略保持原样。版本仍为 v0.0.19，保留 1116 公告，不新增页面公告。

修改前基线：`d094253fb7233a22348fbd8e773ed07b079c70c9`；本地分支：`fix/v0.0.19-ai-input-retention`。基于干净工作区切分支后修改，尚未授权上传；不启动或更改代理。

## 原因与修复位置

不是所有丢字都来自请求失败：有些入口打开时直接清空，有些返回时明确丢弃，有些把无效生成结果误判为成功，提前清掉要求。

| 入口 | 原因 | 本轮行为与源码入口 |
| --- | --- | --- |
| 手动新建书籍／一键开书 | 每次打开初始化表单；再次失败可能恢复第一次旧配置 | `openNewBookModal` 只在上一本成功创建后初始化下一本；保留主题、书名、世界观、要求和勾选。每次请求更新失败快照 |
| 一段话／团队开书 | 打开入口重置想法、方案、原文和阶段；二次要求在请求前被清空 | `activateTeamBookInput` 恢复当前草稿；`retryTeamPlanner` 失败不清二次要求，重复重试不反复追加相同文字；未写入结果可选择“保留并返回” |
| 未完模式继续规划 | 每次进入重新初始化 | 每本书和分支分别保留，与普通团队新书草稿分开 |
| 单个／批量 AI 新建角色 | 模板点击表达式直接清描述，批量数量重置为 3 | 统一 `openAiCharacterInput`；描述和数量按书／分支恢复。草案弹窗新增“返回修改要求”，错误／停止后可返回，已有待审候选先确认再放弃 |
| 设定／大纲／批量细纲工作台 | 恢复审阅时清设定要求；细纲跳往角色／资料时清全部要求 | `restoreWorkbenchAiInputs` 按书／分支恢复；跳转选项改成“保留要求并前往”，保留批量与各章要求 |
| 章节 AI 编辑 | `openAiEdit` 每次清要求和选段 | 按书／分支／章节保存当前页面的要求、选段和待审结果；正文变化后保留要求，不恢复过期定位；生成和采用前检查目标章节 |
| 沉浸 AI 扩写 | 重进扩写从已保存审阅或默认值重置 | 返回手写后恢复要求、字数、模式和标记；原文变化后不套用旧段落标记 |
| 分支重写 | 每次打开通用输入弹窗都采用空初值 | 按书／分支／目标章节恢复未提交要求 |
| 已有细纲覆盖确认 | 弹窗里补写的要求在取消后消失 | 按覆盖范围恢复；若主输入区已另行修改，采用新的主输入，不用旧弹窗草稿覆盖 |
| 生图提示词弹窗 | 取消后只从旧图片提示词重新打开 | 按图片和版本恢复修改；来源改变时采用新来源 |
| 对话类型、预设、文风、单个／批量世界观模板生成 | `{}`、`[{}]` 或空白核心字段可能当成成功并清要求 | 五个生成函数检查实际必填文本；整批有效才写入。网络错误、无效结果保留要求；成功也只清发送时仍未改变的输入 |

共用的临时草稿由 `aiInputDrafts` 保存，`getAiInputDraftKey` 隔离书、分支和目标；不新增 localStorage、数据库或书存档字段。普通改名弹窗不启用此草稿功能。未提交输入不会因为关闭、重开自动发送请求。

原本已经保留的入口没有重复改造：单章细纲的 `co.aiInput`、流水线层的 `layer._aiHint`、普通正文续写要求及最高优先要求仍走原有流程。角色补全和角色工作台生成没有额外“作者要求”弹窗，原档案仍是其输入；不改写角色事实或记忆内容。

## 验收方法与结果

使用项目主目录构建的 `index.html`，在本机已有 Edge 的临时资料中，通过 `http://127.0.0.1:4191/index.html` 验收。不读写日常浏览器书库。模拟配置是 OpenAI 兼容协议、模型名 `gemini-retention`，目标 `https://retention.invalid/v1`；请求被页面内 mock 拦截，其他外发拒绝。没有调用真实模型。

实际输入包括“只增加心理动作，不改变事实”“返回后新补充的要求”“补充：主角不要失忆”；两本合成书各含一章和细纲。响应分别模拟 HTTP 400、空对象／缺字段对象和挂起后停止。Gemini 输入改写与抗截断全开／全关分别运行，记录实际请求的工具封装状态。

执行命令：

```powershell
npm.cmd run audit
node --test scripts/v19-ai-input-retention.test.cjs scripts/v19-ai-input-validation.test.cjs
node scripts/v19-outline-review-browser.cjs --ai-input-retention
npm.cmd run gate
npm.cmd run gate:browser
```

专项单测 31/31，通过取消、提交重开、书／分支隔离、正文变化、五类无效输出、合法成功、请求期间新输入等场景。浏览器专项 55/55，通过错误、停止、连续两次失败、新书与继续规划分离、工作台切书、细纲跳转往返、生图提示词取消重开及真实按钮点击。

普通门禁9/9、完整浏览器门禁27/27，失败／跳过均为0；v19功能单测363/363。完整门禁共1487.9秒，覆盖评论费用与超长保留、全文章数保存刷新、角色和旧格式导入、作者设定、关系图、站点入口、快照、百万字合成旧书、手机和平板可视区、旧版浏览器对照、规划中断／手动恢复、真实文本本地分卷重放、三层分支实际请求和设置搜索。逐步命令、耗时和输出尾部见 [gate-browser.json](evidence/v0.0.19-ai-input-retention/gate-browser.json)，完整步骤日志见 [gate-browser.log](evidence/v0.0.19-ai-input-retention/gate-browser.log)。

布局覆盖 1280×800、1024×1366 触屏平板、768×800、360×740、320×740，均测明暗主题。实际输入后点关闭并重新打开，错误结果页“返回修改要求”按钮实测高 44px、处于可视区、中心点击命中、无横向溢出。10 张截图和逐项断言见 [证据目录](evidence/v0.0.19-ai-input-retention/)。

结构审计通过：标签无跨层、配对无缺失，editor-head 的 div 为 6/6；没有新增存储键或数据库、没有重复声明，删除符号无残留。源模板同步构建到主目录 `index.html` 与 `assets/js/moyun.js`。

本轮模板只增改按钮，没有增删 div，差异中 div 开闭均为0。暂停范围的四个核心函数与基线相同，见 [scope-review.json](evidence/v0.0.19-ai-input-retention/scope-review.json)。

## 验收中发现并处理的测试问题

- 旧 VM 测试按旧行为加载函数，缺少本轮新增辅助函数，团队离开断言仍要求丢草稿。夹具改为加载实际辅助函数，断言更新为保留／留下／写入三种选择；没有向产品加测试专用空函数。
- 细纲覆盖测试使用未完模式书，按原规则进入追加卷纲而非覆盖确认。隔离场景改成关闭未完模式，产品规则不变。
- 布局断言曾在弹窗缩放动画中间读取到 43.9px。测试等待实际高度达到 44px 后再量布局并点击，没有调低断言，也没有等待无限循环动画。

## 边界与手动复验

本轮保证的是**当前页面内返回、报错和重新打开**。临时草稿不落盘，刷新页面、关闭标签页或浏览器崩溃后恢复尚未提交输入，不在本轮实现范围；已写入书库的内容仍沿用原保存。作者明确应用成功的生成任务按原规则结束本次输入，不会把旧要求悄悄用于下一本书。

尚未覆盖真实服务商的失败形态、iOS／厂商浏览器真机键盘、断电恢复。自动化已覆盖范围内未发现输入丢失；不把本地 mock 称为真实模型兼容性确认。

可手动复验：AI 新建角色填写一段描述，关闭重开；用无效 API 生成后点“返回修改要求”；一键开书失败后返回修改主题，再次失败并返回；团队二次修改失败后返回手填再重开；每次比较原文字与勾选是否完整。
