## 存档与实现

上一轮稳定状态为 3901d4e4f6eadcae1fc0405b616b9b572970d47e。已建立 backup/v0.0.19-before-comment-truncation-20261122 备份分支，开发位于 feat/v0.0.19-comment-truncation。评论基础改动单独提交为 6a32c94；8826d7e 补齐通用完成处理、截断设置与验收；aebf8c1 只修正旧浏览器测试的上下文准备与设置位置。产品候选为 8826d7e，最终整套复验基于 aebf8c1，之后仅归档报告和证据。回滚时切到备份分支即可恢复上一轮代码，不改用户浏览器资料。

- 全局设置 → 上下文 → 书评数量上方新增“评论自动跟随生成”，默认开启，沿用既有书评团总开关。关闭自动跟随后，手动生成本章书评仍可用。首次生成、正文重生成和中断续写均复用同一完成处理函数。
- 原“书评随正文生成”更名“评论与正文合并生成”，保留现有功能和说明。旧名称仍可搜索。
- 书评数量支持 0–20；0 不再被默认值表达式当作 8。自动和手动章节书评入口在读取 API 配置之前统一拦截，反复点击不发请求、不覆盖旧评论。JSON 和文本评论均受数量限制。数量为 0 时显示“ⓘ 不生成”，复用已有通用提示，支持鼠标悬停、键盘聚焦和手机点按；点按提示约 3 秒后消失。
- 三轮摘要补写下方新增“截断设置”，默认开启以保留旧行为。实际失控线为 max(1200, round(目标字数 × 2.5))，说明随当前正文目标显示实际字数。关闭时取消流式超长中止及正常生成／中断续写的超长保存拦截；正文、摘要、评论仍使用原解析流程。服务商 token 上限、断流识别和其他内容校验保留。
- 新设置沿用 settings 和现有 IndexedDB 保存队列，不新增 localStorage 键或数据库；不修改书稿、角色、旧记忆、自动总结策略或 API 发送流程。UI 沿用现有开关、按钮、输入框和提示组件，没有新增 CSS。

## 验收方法与输入

执行目录为 Moyun；环境为 Windows、本机隔离 Edge、HTTP 127.0.0.1:4191，独立临时浏览器档案，结束自动关闭清理。所有请求拦截到 comment-truncation.invalid 的本地 mock；禁止外发，不调用真实付费模型、不启用代理。

执行命令：

    npm.cmd run audit
    npm.cmd run gate
    node scripts/v19-outline-review-browser.cjs --comment-truncation
    npm.cmd run gate:browser

专项使用 OpenAI-compatible SSE 和非流式 JSON 响应，正文／评论分配不同测试模型 gemini-writing-local、gemini-comments-local。Gemini 输入改写与抗截断全开、全关各测一次；全开时真实经过项目 output_reply 解码，返回工具参数按 240 字分片。没有另写 AI 发送通道。

## 验收边界

在已覆盖范围内未发现未解决问题。没有使用真实服务商或用户手机／iOS／厂商浏览器进行调用；不同服务商的 token 额度和返回格式仍需公测确认。关闭本地字数截断不能使服务商无限输出。当前未部署，线上站点仍保持上一轮。
