# v0.0.19 实测清单与提示词

配套文件：docs/V0.0.19_PLAN.md（要求与验收）、docs/V0.0.19_STEP_LOG.md（开发者的步骤记录）。
开发者做完 v0.0.19 后，请按本清单实测，把结果和新版本一起交回来。我会据此做下一轮检查，并提出修改方案。

## 1 这份清单查什么

- 开发者的验收（PLAN 里的 F、W、C、K、B、D、R、T、U、Q、SM、I、V、N、X 编号）用假 AI 和夹具跑，只能证明程序逻辑对。
- 本清单（RT 编号）用真实模型、真实书、真实手机跑，专查假 AI 查不出的事：真实模型守不守格式、提示词效果好不好、手机上手感、老书有没有被弄坏。
- 优先级：P0 数据安全，先测；P1 核心功能；P2 体验。P0 有一项没过，先停下回传，不必测完。
- 不要凭感觉写「正常」。每项写做了什么、看到什么，附截图或日志。

## 2 开始前

### 2.1 环境
- 新建一个浏览器用户资料来测，不要用平时写书的那个。
- 先把你真实书库完整导出备份，放到安全位置。
- 测试地址用本地预览 http://127.0.0.1:4176/（npm run preview），不要用线上地址（本版还没上传）。双击打开和 localhost 是两个存储来源，书库不共享，不要混着测。
- 配好真实 API，记录协议和模型名，写进回传表。不要把 API Key 发给我。

### 2.2 设备
- 电脑浏览器宽度 1280 一个，开发者工具模拟 1024、768、414、360、320。
- 手机真机至少一台，记下浏览器和系统版本。iOS 如果有，单独测并标注，没有就写「iOS 未测」。

### 2.3 测试书
- 夹具 A 到 F：用 scripts/v19-make-fixtures.cjs 生成后导入。A 空白书；B 老版本书（30 章、2 分支、1 卷）；C 大书（100 章、3 分支、30 条设定、100 章细纲）；D 只有 35 章细纲没有大纲、没写到结局；E 细纲 12 章、已写到结局；F 单章 8000 字纯手写章节。
- 另用真实模型新写一本「实测书」，3 章以上，用于分支和衔接测试。

### 2.4 怎么拿证据
- 写作框旁的「真实上下文」按钮：看 AI 这次到底收到了什么。
- 浏览器开发者工具的 Network 页：看请求次数、请求体。
- 设置里的导出：导出文件里搜关键词，看数据在不在、在哪一层。
- 截图命名：RT编号-序号.png，例如 RT-B1-2.png。控制台报错截全。

## 3 回传格式

每项一行：

| 编号 | 结果（过 / 未过 / 未测） | 证据文件 | 你看到的和期望有什么不同 |
|---|---|---|---|

另附：
1. 实际用的协议、模型名、浏览器和版本、手机型号、测试日期。
2. 开发者的 docs/V0.0.19_STEP_LOG.md。
3. 新版本的获取方式（分支名或压缩包）和回滚标签 v0.0.19-base。
4. 第 14 节的提示词评分表。
5. 导出文件如果要发给我，先去掉 API Key 和不想公开的正文。
6. 没测的项目写「未测」和原因，不要空着。

## 4 P0 数据安全

### RT-A1 老书兼容（对应 X-03、B-03）
步骤：导入夹具 B，逐个打开章节、细纲、分支、卷，不改任何内容，点保存，刷新，再导出。把这份导出和导入前的导出用文本对比工具对比。
期望：章节、细纲、分支、卷、暗线内容一字不变；只允许多出新字段（branchData、staleMarks、writingRequirement、bridge 等），并且是空值。
失败时回传：两份导出的差异截图。

### RT-A2 分支存档往返（对应 B-14、B-15、K-06）
步骤：用实测书建 1 个分支，在分支里改一章细纲，加一条暗线。依次做：保存、刷新、导出、在新的浏览器资料里导入、备份恢复。每一步后都打开主线和分支检查。
期望：各分支细纲和暗线都在，不串；导出文件里原字段 chapterOutlines 是主线版本，不管保存时在哪条分支。

### RT-A3 突然关闭（对应 B-17、X-07）
步骤：切到分支，在该分支某章细纲里写下标记「RT-A3-标记」，不要点别的，等 3 秒（自动保存有 2 秒防抖），直接关闭整个标签页（不要走页面里的退出）。重新打开。
期望：回到关闭时所在的分支，标记还在；切回主线，主线细纲里没有这个标记。

### RT-A4 旧版本打开新存档（对应 B-16）
步骤：检出标签 v0.0.19-base，npm run build 后预览。导入 v0.0.19 导出的、含分支细纲的存档。
期望：不报错，主线完整可用，只是看不到分支细纲。

### RT-A5 存储提醒（对应 K-01 到 K-03）
步骤：在控制台粘贴下面一行，再触发一次保存或切书。再把 usage 分别改成 92、98，各触发一次。

```
navigator.storage.estimate = async () => ({ usage: 85, quota: 100 });
```

期望：85% 弹 warning；92% 弹 error，停留更久；98% 时开始一键开书、批量生成、新建分支前先有确认框。同一级别同一次打开页面不重复弹；导出备份后 80% 级不再弹，90% 级仍弹。

### RT-A6 保存失败与 IndexedDB 不可用（对应 K-04、K-05）
步骤：按开发者在 STEP_LOG 里写的触发方法各做一次。没写清触发方法就写「未测」，并在回传里提醒我。
期望：出现持久的 error toast，内存里的内容还在，仍能导出；IndexedDB 不可用时提示「数据暂存在小容量位置」。

### RT-A7 紧急备份在分支上（对应 B-23、K-09）
步骤：在分支里编辑细纲后，按开发者在 STEP_LOG 里写的办法触发紧急备份并恢复。
期望：恢复后主线字段没有被分支内容污染。

## 5 P1 分支（项目1）

### RT-B1 串线体检（对应 B-01、B-02、B-08，最重要）
准备：新建空白书，设定里写「主角林远，三十岁，旧书店店员」。依次在续写框输入并生成：
第 1 章：林远在旧书店发现一封蓝色信封，信封上没有收件人。
第 2 章：林远拆开蓝色信封，里面是一张通往港口的船票。
第 3 章：林远沿着港口走到红色灯塔下，遇见一个戴帽子的陌生人。
然后为第 1 到 3 章生成一条范围总结，并确保记忆和暗线里至少各有一条涉及「红色灯塔」。
从第 2 章点「从这章分支」，进入分支。在分支的第 3 章细纲里写：林远没有去港口，而是把蓝色信封烧掉了。在续写框输入「林远决定烧掉蓝色信封」并生成分支第 3 章。
检查：点「真实上下文」，分别查看分支生成时和主线生成时收到的内容。
期望：
- 分支收到的内容里搜「红色灯塔」，一处都没有（前文、记忆、总结、细纲、暗线、章节索引六项都查）。
- 分支能看到第 1、2 章的内容（分叉点之前的主线要读到）。
- 回到主线重新生成第 3 章，收到的内容里搜「烧掉」，一处都没有。
每一项写「安全」或「串线」，串线的写出在哪一项。

### RT-B2 细纲分支（对应 B-05 到 B-07）
步骤：在实测书的第 2 章细纲点「从这章分支」。检查新分支的第 1、2 章细纲和主线一致，第 3 章起为空白。在新分支里改第 1 章细纲，切回主线看主线。再回主线改第 2 章细纲（新分支没改过那一章），切到分支看。
期望：新分支前 2 章同主线、之后空白；分支里改的不影响主线；主线改了分叉前没改过的章，分支跟着变；分支里改过的章不变。

### RT-B3 暗线（对应 B-10）
步骤：主线暗线加一条「红色灯塔的秘密」，布置第 1 章，推进第 3 章。进入分支，点「本章回收」。切回主线。
期望：分支里三个「本章」按钮可点，只影响分支；主线这条暗线没有被标回收。

### RT-B4 四个入口（对应 B-11、B-12、B-13）
步骤：依次从正文顶部、大纲工作台、细纲工作台、暗线工作台各打开一次分支面板；在暗线工作台里切换分支，看其他三处。再试：有章节正在编辑时切换；AI 正在生成时切换。
期望：不点按钮什么都不显示；四处节点的统计各不相同且正确；在任一处切换，其余三处同步；编辑中弹确认，生成中提示先停止。

### RT-B5 分支里不能再分叉（对应 B-09）
步骤：在分支里点「分支重写」和「从这章分支」。
期望：被拦住，提示是白话（分支里不能再分叉，请先回到主线）。

### RT-B6 删除分支（对应 B-18）
步骤：删除一个分支。
期望：确认框写明将删几章正文、几章细纲、约占用 KB；删除后主线和其他分支的细纲、暗线、正文都在。

### RT-B7 大书性能（对应 B-20、B-21）
步骤：导入夹具 C。打开分支面板、切换分支、关闭，各做 3 次，用秒表或开发者工具的 Performance 记录耗时；记录一次保存的耗时。
期望：不卡顿；面板里每条分支有约占用 KB。超过 8 条分支时有提醒。把耗时数字写进回传。

### RT-B8 手机（对应 B-22）
步骤：手机真机或 360 宽，打开面板。
期望：面板从底部升起，默认是列表视图，三个按钮点得到；切到「图」时只在图框内拖动，页面不横向滚。

### RT-B9 本分支走向（对应 B-25）
步骤：在分支里填写「本分支走向」，生成一章，看「真实上下文」。
期望：分支的提示里有这句话，主线的没有。

## 6 P1 卷纲（项目8）

### RT-C1 用户指定卷数（对应 V-02、V-03）
提示词（填进新书的大纲生成要求）：

```
写一部约 40 章的都市悬疑小说，讲一个失忆的法医在三个城市之间追查十年前的一桩旧案。请分成 4 卷。
```

期望：4 卷；章节范围连续不重叠（例如 1 到 10、11 到 20、21 到 30、31 到 40）；每卷有写作内容要求和与下一卷的衔接点。

### RT-C2 不说卷数（对应 V-03）
提示词：写一部约 30 章的古代言情，女主是药铺学徒，被卷入一桩宫廷旧案。
期望：大约 3 卷，每卷约 10 章。

### RT-C3 短篇（对应 V-04）
提示词：写一个 8 章的短篇科幻，讲一艘飞船上的最后一名乘客。
期望：只建 1 卷。

### RT-C4 细纲只读相关卷（对应 V-06 到 V-08）
步骤：用 RT-C1 的书，先不写正文，生成第 2 卷的细纲，点「真实上下文」。再生成第 1 卷和第 4 卷的细纲。
期望：第 2 卷收到的卷信息只有三样：第 2 卷的写作内容要求、第 1 卷的衔接点（第 1 卷没写正文时）、第 2 卷自己的衔接点；搜第 3、4 卷的卷名，没有。第 1 卷没有上一卷、第 4 卷没有下一卷，都不报错。

### RT-C5 卷边界在批次中间（对应 V-11）
步骤：把细纲批次设成 5 章，让某一卷的边界落在第 8 章后，生成细纲，看每批收到的章号范围。
期望：没有一批跨两卷。

### RT-C6 已有卷的书（对应 V-13）
步骤：对夹具 B 重新生成大纲。
期望：AI 建议新增卷时以确认卡显示（查看、全部添加、取消），没有擅自加；已有的卷没有被删。

## 7 P1 重新生成与衔接（项目3、G3）

### RT-D1 历史与可不填的要求（对应 R-01 到 R-06）
步骤：夹具 E，选第 3 到 8 章，整体重新生成两次：第一次要求框留空；第二次填：

```
每一章结尾都要留一个小悬念，语气更紧张。
```

期望：覆盖前的确认框保留原有警告并有可不填的要求框；旧稿都在各章「历史」里；第二次的新稿体现了要求；历史最多 3 条，第 4 次后最旧的被删；恢复旧版后当前稿进入历史。

### RT-D2 构造冲突（对应 C-03，最重要）
步骤：夹具 E，把第 5 章细纲改成「主角在本章中途死亡」。然后只重新生成第 4 章，要求框填：

```
本章结尾主角平安到达新城市，并签下十年的租约。
```

期望：系统提示第 4 章到第 5 章的衔接问题（白话说明，比如主角刚签下十年租约却在下一章死亡），第 5 章细纲一字不变；点「让 AI 调整第 5 章」后一定出红绿对比，确认才写入。

### RT-D3 范围重写锁定（对应 C-02）
步骤：重新生成第 6 到 8 章，生成前后各导出一次。
期望：第 5 章和第 9 章一字不变；检查结果覆盖范围两端和范围内的衔接。

### RT-D4 失败不丢稿（对应 R-04）
步骤：把 API Key 改错，点重新生成。
期望：提示白话错误；旧稿不变；历史不增加。

### RT-D5 大纲、卷纲、正文（对应 R-12 到 R-14、C-11）
步骤：各做一次重新生成。大纲：重新生成并审阅完成；卷纲：重新生成第 2 卷；正文：重新生成某一章。
期望：大纲给出「影响 X 卷 / Y 章细纲」并标待核对，细纲没有被自动改；卷纲让相邻卷标待核对；正文让下一章标待核对，章节「更多」里的「衔接检查」能给出判断。

### RT-D6 关闭自动检查（对应 C-06）
步骤：关闭「重新生成后自动检查衔接」，开着开发者工具 Network，重新生成一章细纲，数请求次数。再打开开关做一次。
期望：关闭时请求数比打开时少，且和 v0.0.18 一致。

## 8 P1 开书（项目5）

### RT-E1 一段话开书（对应 T-01 到 T-06、T-10、T-11）
分别用下面三段话各开一本书。

短：
```
写一个会说话的猫帮失业的程序员破案的轻松故事。
```

中：
```
主角叫沈砚，三十岁，是被公司辞退的消防工程师。他搬进一栋老楼后发现每一层楼的时间流速不一样。反派是物业经理周伯，看起来和善。我希望前期轻松，后期逐渐压抑，结局留白。
```

长（含 8 条明确要求，用来测审查）：
```
写一部现代都市奇幻，共 30 章。1，女主叫许知夏，二十八岁，是修复古钟的匠人。2，她有一个只在雨天出现的搭档，叫阿澈。3，故事发生在一座叫雾港的城市。4，全书必须有一座钟楼。5，第一卷结尾，许知夏必须发现自己的师父还活着。6，不要出现任何战争场景。7，主线是找回被偷走的三枚钟摆。8，结局要温柔，但留一个小遗憾。
```

期望：
- 点「接受」之前，书里没有任何新内容（导出核对）。
- 拆分方案卡片有书名候选、角色名单、卷划分、用户原话事实清单、预计请求数。
- 长段话的事实清单里 8 条都在，来源标「用户」。
- 进度界面能看到多块同时进行。
- 全部完成后，主角名、书名、卷名在设定、角色、大纲、卷纲、细纲里一致（导出后搜名字核对）。
- 审查结果里能看出 8 条要求哪些落实了，哪些没有。
记录：总耗时（点接受到全部写入完成）。再用旧的手填一键开书，同一段话再开一本，记录耗时，写进回传。

### RT-E2 改一句再拆（对应 T-03）
步骤：长段话方案出来后点「改一句再拆」，输入：

```
把女主改成男主，名字叫许知秋，其余不变。
```

期望：方案更新为男主，其余要求仍在；书里仍然没有新内容。

### RT-E3 某一块失败（对应 T-07）
步骤：把「角色员」用的模型改成一个不存在的模型名，再点接受。
期望：只有角色员失败并显示「重试 / 查看原文」，其他块继续；改回正确模型后单独重试，成功；不影响其他块。

### RT-E4 停止（对应 T-13）
步骤：进行中点「停止」，再刷新。
期望：所有请求中止，书里没有半成品，书架里没有残留的空书。

### RT-E5 手填入口（对应 T-18）
步骤：不点「一段话开书」，用原来的方式开书。
期望：和 v0.0.18 完全一致。

### RT-E6 手机（对应 T-16）
步骤：手机上走一遍 RT-E1 的中段话。
期望：弹窗可滚动，进度卡片不撑破屏幕，状态有文字不只靠颜色。

### RT-F1 未完模式（对应 U-01、U-08）
步骤：新建书勾选未完模式，用 RT-E1 的中段话开书。
期望：只有 1 卷、10 章细纲；大纲停在悬念处，没有结局；用「真实上下文」或 Network 看请求，提示词里有「禁止写结局」。

### RT-F2 置灰与继续规划（对应 U-02 到 U-05）
步骤：已有大纲的书打开未完模式开关；然后在未完模式的书里点「继续规划下一段」，输入「接下来主角发现物业经理的真实身份」，把正文一直写到第 10 章。
