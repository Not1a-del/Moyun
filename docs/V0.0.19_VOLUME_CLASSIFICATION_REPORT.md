## 问题与修复

用户提供的 F:/yydcm129/素材/deepseekv4.1falsh测试文本.txt 明确写出三卷：烬灯引·无名灯（1–10）、鎏金帖（11–20）、初灯语（21–30）。固定样本为 scripts/fixtures/v0.0.19/deepseekv41-text-planning-response.txt，与原文件 SHA-256 均为 E3CD9EA2EF3DF35E34ECCCDD52962296A0213E73E14107005275745C9A0E5E65。

只跑旧解析函数已经能得到三卷，不能据此认定页面已修好。本轮先补失败断言，复现了两处后续限制：作者输入“保留第1章”被当成总章数 1；生成入口把书内旧的 chapterCount:10 当作硬性上限。格式修复失败后还会猜测均分，把错误伪装成可用卷纲。用户原书和当时完整输入没有提供，以上是已复现的错误路径，不冒充已核实用户当时的全部触发条件。

现已调整：

- 共用提示优先要求 {outline, volumes:[...]}，每卷一个对象；不能输出合法 JSON 时给出独立卷标题、范围、逐章章纲、写作要求和衔接说明。删除同一请求内重复且冲突的格式要求。
- JSON 优先；无有效结构时用卷标题、中文卷号、分行字段、Markdown 标题等关键词识别。正文中的卷号引用不当成新卷，无关 JSON 数组不当成卷纲。卷后的总纲小节不混进最后一卷。
- JSON 能读出对象但卷范围倒置或重叠时，也继续识别同份原文中的卷标题，不让坏的结构化片段挡住正确文本。非法小数章号和负数仍交由校验拒绝，不取整猜测。
- 细纲工作台同样执行范围校验后的文本兜底。本轮补测先复现了“坏 JSON + 正确文本”在该入口仍失败，再修复，防止只修好普通大纲入口。
- 单章引用不作为全书总数；旧章数仅作缺少范围时的参考。有效卷范围、作者明确总数与明确卷数仍需连续、无重叠等校验。
- 大纲生成保留原有的最多一次格式修复；仍失败就进入手动整理，不猜测均分、不覆盖旧卷。修复过程中保留完整原始回复，包含 JSON 中的总纲，不只保留抽出的卷数组。
- 成功审阅也有“改为手动选择原文”。最近一次成功原文随书保存，大纲页可再次打开；卷纲没有变化时也保留本次原文。一键开书成功原文同样随书保留。
- 手选仍复用现有弹窗、草稿、分区填写、对比及保存流程。用户确认前不修改正式数据；确认后撤下同份原文的自动候选，避免后来误接受时覆盖手选内容。
- 写作要求、三段衔接归到各自字段。逐章章纲即使出现在衔接之后，也归到卷摘要。全部沿用书籍 IndexedDB 和 DB.saveLibrary，没有新增存储键或数据库。

## 验收方法

固定样本用本地 HTTP 页面和隔离、无 MOD 的无头 Edge 重放，API 域名为 https://classification.invalid/v1，密钥为测试占位值；没有连接真实服务商。

node scripts/v19-outline-review-browser.cjs --volume-classification 由 npm run gate:browser 自动运行：

1. 创建旧章数为 10、只有一卷的测试书，留一条“原细纲哨兵”，输入“保留第1章，继续完善故事大纲”。通过正式 generateOutline 发送分块 SSE，以用户原文响应。核对三个候选范围、全部逐章章纲、写作要求和衔接字段；接受前旧数据不变。
2. 点击成功状态的手动入口再返回，确认没有修改原卷；先确认大纲、再确认卷纲，实际写入三卷。保存、真正导航刷新，核对三卷、原细纲及完整原文仍在，再点击“从最近生成的原文手动整理”。
3. 以上在 1280×800、360×740、320×740，明暗主题，Gemini 输入改写与抗截断全关/全开组合重复。全开时使用 Gemini 模型名与项目 output_reply 工具承载，关闭时为普通兼容接口；检查请求确实流式、工具字段开关正确、新增手动入口至少 44px、弹窗边界及无横向滚动。测量等待弹窗及其内容的有限入场、离场动画结束，不把动画中的缩放当成最终尺寸，也不在上一弹窗尚未消失时误点被遮住的下一入口。
4. 在 360×740 的细纲工作台准备 30 条原细纲，实际点击生成按钮，分别重放真实文本、坏 JSON 加同份真实文本，进入卷纲候选、确认三卷，并核对 30 条原细纲逐字不变。Gemini 两项开关全开、全关分别执行。
5. 单独重放合法 JSON；自动成功后在原文输入框选中一段，点击填入、预览、确认，只替换明确指定的卷。核对无额外 AI 请求、旧自动候选撤下、原大纲和细纲不变。
6. 分别返回范围损坏的文本与 JSON，让一次修复请求失败。核对恰好两次请求、原卷纲不变、完整原文保留、可进入手动整理；JSON 中的总纲不能丢失。

新增单元回归覆盖真实三卷、旧默认值、单章引用、关键词格式、字段分类、成功原文保留及手选后撤下候选。旧 V-09 从“失败后必须均分”改为“失败后保留原文、停止自动采用”。浏览器旧断言从“衔接全部混在摘要里且超过2000字”调整为独立检查衔接字段超过2000字、两段各100次重复完整、三段标题齐全，并分别核对逐章章纲。这些调整都先在当前页面复现旧断言失败，没有更新预设 golden。

## 边界

本轮用真实模型曾返回的文字做本地解析和浏览器重放；没有发起在线 DeepSeek、GLM、Gemini 请求。原有门禁另覆盖原生协议模拟，不能据此宣布所有服务商都兼容。真实限流、长超时、iOS Safari、手机真机长按选字和软键盘未覆盖。

不能保证未知格式永远自动识别成功。当前保障是范围不可靠时停止自动采用，保留原文，并允许用户随时手动指定分区；自动识别成功也仍应核对剧情归类是否符合作者意图。正文、细纲不会因为模型返回了额外字段而在本轮卷纲确认中被自动替换。
