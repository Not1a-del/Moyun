# v0.0.19 通用规划解析与中断恢复验收

日期：2026-11-15。修改及构建均在主目录 Moyun，分支 v0.0.19/L1-foundation。基于本地提交 8ef31d2 继续修复；保持 0.0.19，不新增网页公告、不上线、不推送。

## 更新说明

- 规划解析改为与服务商无关的共用函数 normalizeOutlinePlanningPayload。原 normalizeGeminiOutlinePayload 只保留兼容入口，不按模型名称决定解析规则。
- JSON 支持解释文字、代码围栏、嵌套结果、中英文及 snake_case 字段、数组或字典条目。非 JSON 支持独立的“大纲/故事大纲/总纲”“细纲/章节规划/章节索引”“卷纲/卷纲规划”标题，兼容 Markdown、粗体、中文括号、冒号。正文中提到这些词不会直接被当成边界。
- 输出有歧义、多份完整规划或内容中断时，不猜测覆盖正式规划。截断 JSON 可识别已经闭合的章节和卷条目，但仍标为未完成，原文另留待审阅；不将卷对象误归为章节。无效的零、负数、小数章号保留给范围校验，不擅自改成有效值。
- 大纲主动停止、网络断流和不完整规划都会打开已有的异常原文审阅。已有大纲、细纲不被半截结果替换。
- 一键开书失败原文写入 novel.oneKeyRecovery，与书一起由 DB.saveLibrary 保存，不新增 localStorage 键。失败页可展开查看；刷新后可从大纲工作台“一键开书未完成原文”查看当前及上一版失败原文。重开成功后清掉对应恢复记录。
- 非流式回复同样检查 truncated/partial，收到文字后不自动重试覆盖。中断时未开始的模块也列为未完成，便于“全部重开”继续。
- 修复一键开书 core 候选已赋值、后续卷纲处理失败时，收尾仍写入失败候选的问题：失败时恢复模块结果容器，原文单独保留。已经完成并写入的区块仍保留。
- “全部重开”移到失败页底栏“返回配置”左侧；只请求失败模块。两按钮及关闭按钮至少 44px 高，320px 下仍在视口内，可点击。返回配置恢复原输入和选项，本轮在实际页面验证失败、恢复、再次失败、重开和刷新。

没有改动工作台“追加剧情”的 existingChapterNo 引用协议，也没有拿展示用的自动编号去替代旧章引用；该路径仍由原有校验和审阅控制。

### 规划解析样例

1. 用户提供的真实 Gemini 文本：原始文件 F:/yydcm129/素材/gemini3.8flash测试数据.txt，完整 30 章、6 卷。作为回归数据原样保存到 scripts/fixtures/v0.0.19/gemini-planning-response.txt，测试不再依赖本机 F 盘文件存在，也不允许缺文件时静默算通过。该文件只有规划内容，没有 API 凭据。
2. 用同一规划数据构造“解释文字 + JSON 围栏 + result 嵌套”的 DeepSeek 形态模拟回复；另测中文字段、snake_case 字段、字典章节集合和多种独立标题。
3. 截断的嵌套 JSON 包含一条完整章节、一个完整卷及一个未闭合卷：只恢复已闭合条目，类型不混淆，raw 与输入逐字一致，incomplete 为 true。
4. 两份完整规划并存：明确报歧义，不猜哪一份是最终稿；角色数组中的 outline 不被当成全书大纲。
5. 流式断流、非流式 truncated、主动停止：断言收到的文字仍在、请求不因已有半截文字而自动重发，正式规划未被替换。

### 实际页面与请求

- 尺寸：1280×800、360×740；浅色/深色两种主题。通过 toggleTheme 切换并断言实际 data-theme，避免只改变 Vue 状态而截图仍是同一主题。
- 协议：OpenAI-compatible SSE 与 Gemini 原生 SSE。测试配置名“本地规划模拟”，模型标识 deepseek-planning / gemini-3-planning，仅为模拟标识。
- 每种尺寸、主题，分别把 Gemini 输入改写与抗截断全关、全开；两种协议都实际发出流式请求。Gemini 全开时断言 output_reply 工具存在；一键开书的作者输入还断言已转入 read_user_input。其他模型保持普通输出。
- 30 章/6 卷候选进入独立审阅，实际卷数为 6；原“正式大纲哨兵”和“正式细纲哨兵”保持不变。弹窗位于视口内，页面无横向溢出。手机比较区纵向排布且独立滚动，桌面左右比较。
- 在流的首段后抛出网络错误，及首段后等待用户停止：已收到的约 420 字符仍在异常审阅，不能直接接受成完整卷纲，正式内容不变。
- 一键开书失败后，点开原文、返回配置，主题/书名/世界观输入均一致；故意在卷纲格式修复请求抛 AbortError，正式大纲保持不变，当前及上一版失败原文仍在。
- 失败页底栏在 1280/360/320 宽度 × 明暗主题六组实测：全部重开位于返回配置左侧、三个按钮高度至少 44px、中心命中对应按钮、无横向溢出。实际点击返回配置后核对输入，而非只调用恢复函数。
- 再点“全部重开”：只执行 core，实际 1 次请求，成功得到 6 卷并清掉恢复记录；OpenAI-compatible / Gemini 原生及开关全开/全关四组分别执行。
- 最后再次造成失败，等原保存流程完成后真正刷新：大纲工作台能展开恢复记录，显示内容与书内持久化记录一致。

## 边界及尚未确认的部分

在已覆盖范围内未发现问题。真实 Gemini 文本只证明该响应已能本地解析，不证明真实 Gemini/DeepSeek API 的各种行为均已确认。本轮没有连接真实服务商；真实限流、长时间超时、手机真机/iOS 键盘未覆盖。

未知格式不可能全部预先识别。识别不到、多个候选或中断时，应保留原文供查看和重试，不把猜测结果写入正式数据。未来新增样例应加入同一套回归，优先扩展共用规则而非模型专属分支。

一键失败恢复记录保留当前及上一版失败原文，不是无限历史仓库；成功的模块仍按原逻辑保留，不做整本书回滚。本轮不裁剪整段总纲，也不改变上下文 after 默认值。

回滚位置：本轮前提交 8ef31d2；另有 .ui-check/planning-parser-before/moyun.single.html 源码备份。回滚时应同时回退源码、构建产物与本轮脚本；不要覆盖用户的 IndexedDB 书库。
