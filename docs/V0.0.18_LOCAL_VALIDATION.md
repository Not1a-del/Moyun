## 四项优化与验收结论

### 1. 文案与手机界面

Gemini 测试输入下方说明精确为“实验功能”。旧版预设旁显示黄色“（未知兼容性警告，请谨慎使用）”。旧预设长文本、编辑输入和触控按钮已适配窄屏，手机编辑文字为 14px。卡片启用勾选的可见标记固定为 20×20px，手机外层点击区为 44×44px；“作用模块”标签为紧凑 32px 高并按内容宽度排列，窄屏换行，不再被通用按钮规则撑高。

截图验收发现预设编辑弹窗原本嵌在带 transform 的侧栏中，fixed 定位因此被侧栏限制。已将弹窗移到 Vue 工作区根层；1366px 桌面宽度 512px 并居中，390px / 320px 手机使用可用全宽，667×375 横屏可滚动到保存按钮。四尺寸均验证宽度、焦点、滚动、保存按钮可达以及 Escape 关闭后焦点还原。

### 2. 全局温度与思考强度

“全局设置 → 连接中心”下方新增调节栏，并明确标注全局作用范围。温度范围 0–1、步长 0.01、显示两位小数；思考强度沿用 RP-Hub 六档滑块（`none / low / medium / high / max / 默认`），默认不指定强度。选择保存后切书与刷新均保留。

公共文本请求经 `buildAdapterRequest` 统一使用全局值，涵盖正文、续写、建议和记忆等模块；连接诊断明确使用自己的测试参数。OpenAI 使用 `reasoning_effort`，Gemini 按模型适配 `thinkingLevel` 或 `thinkingBudget`，Anthropic 使用 thinking budget，开启时省略不兼容的 temperature 并保证输出预算大于思考预算。协议断言和浏览器实际请求体均覆盖这些接线。

### 3. Gemini 抗截断适配

仅当手动开启且模型名包含 Gemini 时启用，默认关闭。适配 RP-Hub 的 `output_reply` 工具承载正文，兼容 Gemini 测试输入的 `read_user_input`，并为 `openai-chat`、`openai-compatible`、`gemini-generate`、`anthropic-messages` 四种适配器声明工具及强制选择。

流式和非流式共享正文解码，覆盖分段 JSON、Unicode、思考内容、Token 用量与普通文本回退；工具外壳不会写入章节。遇到 `length/MAX_TOKENS` 时，只要已经收到普通正文或 `output_reply` 工具正文就尽量保留并交付，只有没有任何可保留正文时才失败；完全空回复最多请求 3 次。拒绝、过滤、网络中断和损坏 JSON 仍不作为完整结果保存，普通非抗截断请求继续严格拒绝限长结果。抗截断不解除模型输出上限，也不保证服务商一定接受工具协议。

按当前设置重新组装提示词时，抗截断临时略过宿主 COT，不修改预设保存的开关。已有“复用首次注入”重生成行为仍直接使用原消息快照；旧快照中已存在的 COT 不会被追溯剥除。白鸟插件自己的 COT 流程独立保留。

### 4. 记忆库与全局向量模型

- **按章节工作**：schema v2 将旧楼层数量换算为章节（向上取整除以 2）；最近章节范围 1–50，默认 10。逐章总结读取目标章正文及此前最多 N 章原文背景，只总结目标章，不读取未来章节。当前章原始用户输入随章节保留，但不能代替实际正文事实。
- **写作接线**：正文与中断续写均读取记忆；最近 N 章保留原文，更早章节使用有效记忆，缺失、停用或正文指纹过期时回退原文。最近 25 章之外的旧记忆每 5 章合并，原逐章细节仍保留。
- **向量召回**：支持 Int8 向量、相似度阈值 0.48、最多 10 条并按章节顺序注入；更换模型后重建索引，校验数量、索引重复/越界及维度。向量失败回退章节上下文，取消仍中止操作，过期响应不写入。
- **全局模型选择**：页面按钮读取当前有效默认全局 API 的模型，用户手动选择向量模型；模型名保存在全局设置，只在首次迁移读取旧值。切书、导入与刷新不覆盖选择；获取模型时具备加载、错误、超时与站点变更校验。
- **隔离与按钮**：记忆依书籍、分支及正文指纹校验并深拷贝，测试覆盖切书、切分支、正文重写、追加/替换/新书导入。实际 DOM 点击覆盖获取模型、手选、补录、编辑、停用/启用、重新记录、停止，验证晚到响应不串书、不复活已取消记录。

OpenAI 兼容站点的模型列表未必提供 embedding 能力标记，因此列表可能包含聊天模型，需要手动选正确的向量模型；Gemini 按能力筛选。选择名称被保留不代表该模型一定支持向量接口，调用不兼容时走错误提示与上下文回退。

## 接手功能回归

全新临时 Edge 档案首开为 1 本空白书、0 章、16 条新版预设（14 条可见）及 11 条旧预设。旧预设位于分区底部，编辑、开关与作用模块匹配的实际请求注入通过。

卷纲继续保留“承接上一卷、本卷推进与收束、下一卷起笔核对”三段，不再按 2000 字截断；后卷写作请求携带上一卷交接和本卷边界。Gemini 测试输入保持手动开关；只搬移明确标记的本轮作者要求，没有标记时不猜测最后一条 user 层，也不添加随机零宽前缀。Token 用量覆盖多请求、流式累计、0 与缺失字段、切书及刷新。自定义字数覆盖桌面双击、手机触摸长按、小数、300–30000 边界及实际写作请求。旧版预设、导入、AI 建议、插图与图片编辑共五组浏览器回归通过。

### Gemini 测试输入与 RP-Hub 混淆输入对照

对照 RP-Hub 固定提交 `5de32c9475a36ca559561ac98a4b71287b8a410e` 的 `assets/js/app.js` 与 `assets/js/api-utils.js`：两边的核心做法相同，都是把本轮用户内容放入 `read_user_input` 的工具结果，并在对话里留下调用记录和“读取工具结果继续回答”的提示。

触发和细节并不完全相同。RP-Hub 在模型名包含 Gemini 时自动启用，并按来源标记找到本轮已组装的用户消息；墨韵需要用户打开全局“Gemini 测试输入”，且只在 Gemini 原生接口、Gemini 模型上启用，连接诊断不会触发。墨韵只搬移 `_moyunUserInput` 明确标记的本轮作者要求；没有标记时保持原消息，不把最终校验或其他 user 层猜作作者输入，也不添加随机零宽字符前缀。墨韵还把工具记录转换为 Gemini 原生 `functionCall` / `functionResponse` 结构。

与抗截断同时开启时，实际请求仍在历史内容中保留 `read_user_input` 调用及用户输入结果，而 Gemini 强制选择的输出工具仍只有 `output_reply`。新增协议回归断言检查了两者同时出现、输入文本完整，以及输出工具选择没有被输入工具替换。该验证证明请求组装没有互相覆盖，不证明所有 Gemini 服务商都接受这类工具历史；服务商兼容性仍需实用模型验证。

## 尚未由本地测试证明

本轮使用隔离浏览器与 mock 捕获应用实际请求，没有调用用户真实 API 或读取用户密钥。**最大验证空缺是服务商实际兼容性和模型产出质量**：Gemini 工具调用及签名、各模型思考档位、代理站点差异、真实总结遗漏率、卷纲服从度和 Token 字段表现仍需真实使用验证。当前测试证明的是请求接线、解析、存储和异常保护。

手机测试为浏览器视口与触摸事件模拟，未覆盖实体 iOS / Android 软键盘、后台挂起及存储配额差异。超大书库的真实上下文额度、耗时和费用未测；历史记忆缺失时回退原文会增加上下文，开启高思考强度也可能增加用量。
