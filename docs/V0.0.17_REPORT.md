## 2. 重新生图、历史与保存

原实现依靠图片 URL 加载、DOM 替换和 canvas 再下载缓存，不能可靠跟踪任务状态，也没有保留多版本。现在每个图片位置由同一任务管理生成、展示和存储。

- STA1N 增强线路对照 [RP-Hub](https://github.com/STA1N156/RP-Hub) 和 [NAI 页面](https://nai.sta1n.cn/) 实现，使用 `POST /api/jobs` 提交及原任务 GET 轮询，显示服务返回的 `queuePosition`、`queuedCount`、`generationProgress.percent`，不编造进度。
- 提交、排队、生成、保存进度显示在原图区；失败通过原有 Toast 提示一次，图片下方不常驻错误。等待或失败时保留旧图；失败标记阻止重绘自动重试，用户仍可手动再试。连点合并同一任务，轮询暂时失败只查询原任务，不重新提交。
- Canary 直连仍可生成和保存，但其协议不提供队列/百分比，界面明确说明限制。
- PC 端图片上悬停或键盘聚焦时才显示图片角落的小图标：左下角历史箭头，右下角保存与重新生成；离开图片后隐藏，点击图片其他区域仍打开预览。手机端控件缩为 32px 并保持可触达与不重叠。
- 正文“编辑”模式直接显示当前选中版本的提示词文本框；蓝色左右箭头显示为 `当前 / 总数`，可切换历史提示词并同步图片。手写 `[IMG: lighthouse, sea, sunset]`、嵌套权重和换行标签仍受支持。
- 右下角入口打开三个操作：左侧“取消”，中间“AI 改词后生成”，右侧“重新生成”。右侧使用当前选中图片版本的提示词，直接调用生图，不需要文本 AI 配置，也不会读取编辑框中未提交的草稿；中间才读取当前章节正文附近场景、书籍资料和角色资料，调用全局设置中“封面/立绘”模块配置生成最新 tags，再按当前画风提交图片任务。编辑框的“按此提示词生图”直接使用手动编辑的词。
- 位置键包含书籍、章节、原标签和同词次数，不含画风或段落序号。切换画风/尺寸不重新生成整书、不隐藏旧图；前文新增普通段落不破坏图片位置。
- 关闭自动插图或清空密钥仍可浏览已有缓存，旧缓存可迁移。远处无缓存图片待滚动接近后才提交，避免打开长书就将所有图片排队。
- 图片验证通过并完成 IndexedDB 事务后才显示“已保存”。写入失败明确报错，旧图保留，新图仍可立即下载。
- 全量备份包含全部历史及选中版本；导入新书/追加合入重映射书籍和章节归属。先恢复图片再挂载书籍，导入期间阻止自动生图；中途失败会恢复已覆盖图片，回滚失败另行提示。
- 切书时停止本地图片等待，不串到其他书；停止等待不等于远端服务撤销已提交任务。

使用说明：点击图片右下角重生图标，在弹窗选择按当前图片的词重生，或让 AI 阅读正文改词后生成；也可在正文编辑模式手动改词后点击“按此提示词生图”。直接改写正文原始 IMG 标签会视为另一个图片位置。保存单图用图片角落的下载按钮，连同历史迁移用“全量备份”。

## 3. AI 建议上下文升级

请求发出时读取当前书籍状态，包含当前大纲、目标卷纲、目标细纲、下一章细纲边界、作者当前输入、世界/角色资料以及当前分支最近五章。

每章优先用非空摘要（含可用的已启用范围摘要），没有摘要依次用 **细纲 → 大纲/卷纲 → 正文**；正文回退剥离图片标签和推演内容，保留靠近结尾的内容。摘要/正文标记为事实，细纲/大纲标记为计划，避免把待写情节当成已经发生。

移除大纲固定前 800 字截断，改用上下文设置并保留头尾；全空书可获取开局建议。连点只产生一次请求；切书/切分支取消旧结果。等待中修改输入或书稿时，旧响应不覆盖当前输入。

## 未验证边界与风险

1. **最没有把握的是实际服务联调。** 没有本轮真实密钥调用授权，未验证当前服务的 CORS、鉴权、付费队列和图片下载，也未实际调用文本模型评估新预设创作质量。模拟通过不能替代这些检查；Canary 的进度能力受其协议限制。
2. **最大的剩余遗漏是大容量备份。** 图片历史增长会占用浏览器存储；现有小说 JSON 导入上限为 50MB，含大量图片的全量备份可能超过。可单张导出图片，但大书仍需后续分包/附件包设计，超大备份没有完成验收。
3. 移动端通过 Edge 尺寸模拟和布局实测，没有在真实 iOS Safari/Android 浏览器验证系统下载、后台挂起和存储配额差异。
4. 数据仍在浏览器本地。清站点数据/清图片缓存会清除图片，本次不提供跨设备自动同步。保留历史不等于永久存储保证。
5. 合作者其他存储与解析重构、任意第三方 MOD、长期大容量压力不在本轮范围。已通过场景没有发现阻断交付的问题，不承诺未来绝无其他问题。
