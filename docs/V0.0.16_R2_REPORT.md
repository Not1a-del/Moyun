# v0.0.16 同版修复（第三轮·侧栏动画性能）检测报告

日期：2026-09-26。状态：本地修复完成，未上传 GitHub。工作分支：fix/v0.0.16-sidebar-performance。修复前代码快照：c0d55f2；用户手动修改保留基线：4e8b20e。

## 用户要求与范围

- 用户反馈新增的侧栏展开/收起动画在长书库（400 章）下非常卡顿，明确授权：若流畅度无法保证，可直接删除动画，优先不影响正常使用。
- 要求所有修复继续计入 v0.0.16，不扩展修改未提出的 UI，不更改任何与本问题无关的功能。
- 用户已确认：动画不是功能、删除不影响正常使用；同时发现收起后残留 1px 边框的既有瑕疵已顺带修复。

## 删除侧栏收起/展开动画

v0.0.16 新增的「桌面侧栏收起/展开时的 240 毫秒宽度平滑过渡」在长书库下每帧驱动整页 flex 重排（正文、弹窗布局、滚动条位置同步重算），无法保证流畅。经实测与验证后删除。

变更内容：

- 桌面端（宽度 ≥768px）侧栏收起/展开的 CSS transition 从 `width .24s ease` 改为 `width 0s` —— 即时切换，无动画。
- 收起功能本身完整保留：「点击侧栏边缘半圆按钮收起 → 侧栏整体宽度归零、inert 聚焦禁止 → 半圆按钮出现在右边缘」这一流程与之前一致。
- 展开按钮（半圆箭头）本身也有宽度 hover 过渡，一并移除，只保留静态背景反馈；其展开功能不变。
- 移动端原有抽屉动画（`transition-transform duration-300`）不受影响，未修改。
- 无其他 UI 变更。

同时修复：收起后残留 1px 边框的既有瑕疵——通过把 `border-right` 从静态 style 移入 `:style` 绑定（Vue `normalizeStyle` 合并时静态样式会覆盖展开分支的声明），确保收起时右边框完全为 0。

## 实测数据

测试环境：隔离 Edge headless + CDP（端口 9236），本地测试服务器（端口 4176），1280 与 390 宽度两种窗口，合成 400 章长书库（188.5 万字符）。

删除动画后的实测：

- 收起/展开单次操作仅剩一个 ~70ms 长任务（与 v0.0.15 基线切换标签的 88-100ms 同级），属长书固有的次性重排，非动画引入。
- 侧栏宽度变化从 240ms 逐帧抖动变为单帧一步到位，帧时间分布正常。
- `buildLibrarySnapshot` 在 400 章下耗时 18-20ms（v0.0.16 性能优化生效，基线 199-220ms），无回归。
- 焦点单项操作在 collapsed 切换流程中为 0ms。

## 修复的既有问题

收起侧栏后，`border-right: 1px solid var(--bd)` 由静态 `style` 声明，与 `:style` 绑定中的 collapsed 分支（`border-right: 0`）被 Vue `normalizeStyle` 合并时静态样式覆盖——导致收起后右侧始终残留 1 像素的空白。本版把 `border-right` 移入 `:style` 两分支出，修复后收起干净无残留。

## 尚不确定

本修复基于合成 400 章长书的测试结果，真实使用场景中如果书库规模远超 400 章，收起/展开时单次重排时长可能增加，但动画本身已删除，不会出现逐帧抖动。手机端抽屉动画为旧有功能，未纳入本轮修改范围。
