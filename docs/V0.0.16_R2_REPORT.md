## 保存失败根因及修复

这是上一轮引入的回归。上一轮把 library_v6 从 JSON 字符串改成 IndexedDB 对象写入，但 buildLibrarySnapshot 的 searchHistory、activeStyleIds 未脱离 Vue Proxy。实际浏览器 structuredClone 复现 DataCloneError，逐字段定位为这两个字段；worldTemplates 中的自定义对象也一并生成普通快照。

旧 DB.set 在 IndexedDB 失败后回退 localStorage。小档案可能表面保存成功，但大库或已有存储占用下会超过容量，从而持续弹出“保存失败”；而旧读取流程优先读 IndexedDB，还可能遮住较新的 localStorage 回退存档。上轮纯空白小样本没有覆盖这些条件，先前报告不能据此证明大库保存可靠。

修复内容：

- 上述字段全部使用既有 snapshotForSerialize 生成普通数据，保留 IndexedDB 对象格式与旧 JSON 格式的读取兼容。
- 凭据、书库和 revision 在同一个 IndexedDB 事务写入，防止部分成功造成不一致。
- 读取回退书库时比较 revision/timestamp，选择较新有效数据；成功迁回主库后才清理较旧回退副本。
- DataCloneError 不再静默回退至小容量存储；其他真实存储失败仍如实报错，不伪装成功。

隔离档案复测：60 万字符书稿，人为禁止 localStorage 书库写入，连续 3 次修改保存均成功写入 IndexedDB；没有克隆错误、回退副本或失败提示。模拟较新 localStorage 档案后刷新，读取新档并保存到主库，数据与 revision 一致。

## 摘要行为

- 首轮提示词明确摘要是必要交付字段，并兼容同一行“剧情摘要：内容”的格式。
- 已有有效摘要时不为摘要增加请求。首轮缺摘要时，二轮可只补摘要；正文也不足时二轮同时扩写正文并返回整章新摘要。
- 二轮用过但仍缺摘要时，可在提醒后进行第三轮摘要请求；三轮只补摘要，不继续扩写正文。设置中有独立三轮开关。摘要失败最多到第三轮，不循环追加第四轮。
- 二轮正文与摘要分开合并，避免首轮摘要把新增正文吞进摘要区；保留剧情时间元数据。
- 正文、重生成和中断续写均检查摘要；补写后摘要进入章节字段，可被后续上下文读取并持久化。
- 关闭、取消、无效响应或接口失败时，正文保留；摘要留空，显示“摘要待补写”并明确警告，仍允许继续生成。不会用前 100 字截片冒充模型摘要。目录中手动编辑或重新生成摘要可解除缺失标记。
- 摘要补写提醒由独立弹窗管理，停止/切书会使旧请求失效；不会借用或覆盖其他业务确认回调。

不能用提示词保证所有真实模型都必然遵从。本轮保证可检测缺失并走明确补救/警告路径，未宣称对任意模型生成的事实准确性作语义证明。
