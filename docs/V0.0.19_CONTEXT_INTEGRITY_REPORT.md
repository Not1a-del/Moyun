## 旧记忆默认保留

- 旧记忆的文本、分组和指纹格式不变。读已有记忆不等于允许重写：新增书级 `autoSummarize` 和 `replaceHistoryWithSummaries`，旧书缺失时均为 false。
- 自动总结关闭时不排后台补录／合并、不自动生成卷末交接、不自动提取时间线、不在写作前重建向量索引；已有有效向量仍可按用户选择的增强模式召回。手动补录只授权当次任务。
- 近期章节先保留原文；预算外旧章仍沿用已有记忆和摘要补足。范围总结、建议摘要、卷交接主动替换近期原文，需要用户显式开启。
- 正文完成不再靠词语邻近猜人物状态并写回档案；即使用户启用自动总结，也不自动改性格、关系或资料。
- 以上开关与内容随 `DB.saveLibrary` 保存，不新增 localStorage 键或数据库。

## 验收方法与实际输入

使用本机已有 Edge 的临时独立档案、本地 HTTP 页面和项目原生 Vue／IndexedDB。拦截 fetch 只允许 `.invalid` 假服务，未向真实服务商发送书稿，也未修改日常书库。

1. `node scripts/v19-outline-review-browser.cjs --reader-onekey`：通过实际 AI 新建角色、审阅接受、保存、刷新，检查林舟／星禾的说话风格、专属约束和对话类型。假 AI 故意多返回全书预设／文风／流水线，确认这些不变；正文实际请求带齐人物与已启用文风。
2. 将上一步数据转换为旧书架顶层镜像，走文件导入、确认、保存、刷新，逐字段比较角色、对话类型、文风选择，逐章比较标题／正文／摘要；再生成正文核实发送。另在角色库头部放入逾万字无关背景，把角色预算降到 100 字，验证末尾点名者在旧格式及设定包两条路径都完整发送。
3. 同一专项复现截图：只勾世界观和负面词，不勾书名简介／大纲／细纲；另测只生成角色、勾选书名简介、勾选世界观但响应缺失。每组预计和实际均 1 次；只有真实缺失组失败。
4. 文本请求采用 OpenAI-compatible 流式 SSE，模型名 `gemini-feedback`；Gemini 输入改写＋抗截断分别全关和全开，全开用真实 `output_reply/content` 工具格式。禁用额外补写、书评、思考和自动重试以准确计数。
5. `--context-integrity`：12 章合成旧书、12 条记忆、1 组合并、2 个角色与有向关系、势力、14 条细纲、2 卷与交接、文风／对话类型／旧预设。测只读记忆、完整备份往返、刷新指纹、追加导入重映射、保存抛 QuotaExceededError 回滚和用户授权开关。
6. 阅读导航使用 180 段合成正文，1280×800 鼠标滚轮；1024×1366、768×800 触屏平板；360×740、320×740 触摸手机；各明暗两主题。检查默认隐藏、快速滚动显示、按钮中心命中与 44px 尺寸、原生点击跳到两端、停止后自动消失和无横向滚动，并保存截图。
7. 完整门禁继续覆盖百万字旧书、手机工具栏／键盘模拟、触屏平板、角色阵营状态色、分支隔离、快照、公测身份和设置搜索；不以桌面结果替代平板、公测入口。

## 测试脚本更新说明

- 旧测试中“自动总结／主动替换”场景显式开启新权限，保持原断言；新增默认关闭和旧记忆不变的反向场景，避免为了过测试把生产默认改回去。
- 预设 golden 文件与内置预设文本没有修改。测试只对历史期望增加本轮明确要求的文风边界一句，其余继续逐字比较，白鸟锁定仍逐字不变。
- 浏览器验收中发现 passive wheel 可能晚于画面移动，现保留上次 scroll 位置计算速度；该失败已补单元回归。
- 测试使用现有公开 saveData 并等待落盘；Vue Proxy 经 JSON 序列化后比较，避免 CDP 返回空代理字段造成误判。新导航的点击检查使用真实 CDP 鼠标／触摸事件。
- 360px 上箭头曾被原主题悬浮按钮遮住，已在手机断点避让，两者中心都能命中；生成时的程序自动跟随不延长导航显示时间。触摸验收等惯性滚动结束后再点击，避免把首触刹停当作按钮失效。
- 角色关系测试曾在关系图关闭动画仍占位时测按钮命中；现等弹窗节点实际离场后再测，仍保留 44px、中心命中和宽度断言。长角色测试用已规范化角色克隆背景资料，避免把正常字段补齐误判为人物档案被改写。
- 首轮完整门禁有上述测试失败，不计为通过；失败回执单独保留，最后一轮从构建开始全部重跑。
- 下一轮站点入口专项曾在设置弹窗缩放动画末尾测得 43.999969px，导致严格 44px 检查失败。改为等 Vue 更新、绘制帧和实际动画结束后统一测量，未放宽尺寸／命中断言；独立专项已通过，再从构建重跑完整门禁。中止的门禁及失败详情仍保留，不拼接成一次成功。

## 边界与用户手验

本地证明的是数据保存和应用最终发送内容，不能保证 Gemini、DeepSeek 等真实模型绝不改人设。请用此前失败的同一本书、同一章节、同一模型复测；在“真实上下文”中核对人物约束和旧记忆，再判断生成质量。真机 iOS／厂商浏览器的触摸惯性、工具栏和软键盘仍需用户手验。

此前私人约 200 MB 备份中的 characters 本身为 0；本轮不能从不存在的独立角色档案恢复角色，也不能证明更早从未丢失。若仍有问题，最有价值的补充是更早正常备份与失败时的实际请求，而不是只看生成正文猜原因。世界资料／总纲仍受原有用户预算和命中规则限制；本轮没有承诺整本百万字原文全部进入单次请求。
