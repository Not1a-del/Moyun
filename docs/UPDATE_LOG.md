## v0.0.9：卷纲识别、防空白补全与摘要/时间链路修复

分支：`temp/v0.0.8-v009-work`（基于 v0.0.8 稳定副本 `c6f69f4`）。本轮按用户 7 项需求逐项修改，全部改动集中在 `source/moyun.single.html`，构建后同步生成产物。

### ① 大纲工作台的卷纲AI识别

- `buildStructuredOutlineInstruction` 把【卷纲更新】改为必选小节，固定逐卷一行格式 `第N卷｜卷名：XXX｜章节 X-Y｜框架摘要：XXX`，无改动也照抄当前值；卷数与章节边界必须与【现有卷纲】一致。
- `generateOutline` 在【现有卷纲】后注入【卷纲输出要求】，要求大纲文本最前面输出该小节；`aiSupplementOutline` 同样约束补齐空白结构。
- `applyAiVolumeUpdates` 重构为先收集再回填：按行解析卷号/卷名/章节范围/框架摘要，超出既有卷数的行被忽略（卷数量不交给模型扩容）；大纲请求统一 `preferStream: true`。
- “AI修改大纲”复用同一提示词链路，修改意见明确涉及卷纲时可更新对应卷。

### ② 卷纲UI：整体收起

- 新增 `novelVolumesBoardMinimized` 状态与 `toggleNovelVolumesBoardMinimized`，卷纲板头部新增“整体收起”按钮。
- 收起后整块卷纲板替换为一条摘要行（“卷纲已整体收起 · N 卷”+逐卷范围），点击“展开卷纲”或摘要行即可恢复；放大编辑快捷行在收起时隐藏。
- 与既有“收起全部/展开全部”互不干扰：整体收起更深一层，单项展开逻辑保持 v0.0.7 行为。

### ③ AI补全不留空白

- `aiSupplementStoryBible`：project 五字段和 worldView 必填，禁留空/禁写“无/暂无/待定”，素材不足须合理推断并标注“（据现有信息推断）”；entries 至少 3 条。保存后仍有空字段时宿主兜底写入占位说明，工作台不再出现“AI已补充却一片空白”。
- `aiSupplementSelectedCharacter`：8 个档案字段全部必填，currentState ≤60字、其余 30-120 字。
- `aiSupplementStoryBibleEvent`：6 字段全部必填（标题≤20/时间≤24/摘要≤60/因果≤80 字），新增 `EVENT_FIELD_MAX` 常量表并在回填处硬截断。
- `aiSupplementStoryBibleEntry`：name/summary/details 必填并有字数上限。

### ④ 事件时间线自动填充约束

- 时间线头部新增“折叠列表/展开列表”按钮；折叠后仅一条摘要节点（项数+当前选中事件），点击展开。
- 事件标题输入 `maxlength=120`、占位提示“建议 20 字以内”，时间文本 `maxlength=40`；`normalizeStoryBibleEvent` 保存层再截标题 120 字。
- AI 事件补充提示词按 ③ 的字段上限约束输出，避免超长标题挤爆阅读区。

### ⑤ 关系图“当前态”字数硬限制

- `normalizeCharacterRelationships` 保存层把 attitude 统一截到 30 字、changeReason 截到 120 字，任何来源（AI、导入、草稿回填）都不会超限。
- 三处输入框（原卡编辑器、角色工作台当前态、草稿审阅）加 `maxlength=30` 与“（30字内）”提示；AI 提示词改为“态度描述(20字以内)”。
- `.moyun-rel-fact-state` 由 `nowrap` 改为自动换行 + `max-width:52%`，弹窗内不再溢出。

### ⑥ 正文摘要分类修复

- 正文生成不再要求模型连带输出读者评论：7 处提示词（主 sysPrompt、续写、修复、白鸟回读、预检、finalCheck、白鸟承载）全部改为“摘要结束后立即停止”，评论仅保留独立的 `generateChapterComments` 调用。
- 摘要提示词统一为 60-100 字；`parseChapter` 保存层新增 120 字硬截断，防模型把书评误灌进摘要。
- `findLastSummaryMarker` 识别范围扩展：`---剧情摘要---` 分隔线、`## 剧情摘要` 标题、`**本章摘要**` 加粗、`【摘要】`、裸“摘要”行和 `Summary` 均可正确切分。

### ⑦ 剧情时间进入AI链路

- `buildChapterMessages` 新增 `storyTimeOutputRule`：前文上下文（已有 `formatSnowwingChapterStoryTimeContext` 注入“剧情时间（独立元数据）”行）中存在上一章剧情时间时，要求模型先读取上一章时间、结合本章正文推进时间，并在标题行前单独一行输出本章时间，格式固定 `【历法或相对时间·时段】` 且须含日期数字或“当日/翌日”锚点，整行 ≤40 字。
- 新书/无时间线时不注入该规则，避免凭空造历法。
- `parseChapter` 既有时间行剥离逻辑负责识别该行，章节保存与重掷路径写入 `storyTime`，编辑模式“剧情时间”字段继续有效。

## v0.0.12：模板结构审计上线——v0.0.10 工作台错位根因闭环 + 防复发机制

分支：`temp/v0.0.12-structure-audit`（基于 v0.0.11 `cc9a8f3`）。本轮为测试与防复发轮：不改任何业务代码（`source/moyun.single.html` 本轮零改动，仅重新构建生成新指纹产物），新增 `scripts/structure-audit.cjs` 结构审计与 `AGENTS.md` 排障手册。

### ① v0.0.10 工作台错位根因正式闭环

- 用户报告线上站（GitHub Pages，部署 v0.0.10 `60f5921`）角色工作台“哪怕是空白角色也错位”。本轮字节级取证：线上 `index.html` 与 `60f5921` 构建产物内容完全一致（仅行尾差异），无头浏览器无法挂载线上页，改用同提交的本地 worktree 孪生站复现。
- 根因确证：v0.0.10 补充轮提交 `038b967` 给角色编辑器头部加“AI 补充进度条”时，把单行按钮区拆成两层嵌套 flex，`<div class="moyun-character-editor-head">` 少写 1 个 `</div>`。浏览器解析 HTML 时把后续全部兄弟节点（档位按钮、4 张档案卡片、“先选一位角色”空态 div）吞进 editor-head 内部，横向 flex 行把卡片挤成 26~30px 竖条——与用户截图完全一致。
- 该 bug 与角色内容无关（空白角色照样触发，已实测）、与长文本撑宽、min-width 缺失、MOD 主题污染等外部分析方向无关（干净构建即可复现）。
- v0.0.11 提交 `a718e05` 在重构别处时恰好补上了这个 `</div>`（`</div></div>`）。v0.0.11 构建产物上空白角色与 1440 字超长无空格双用例、PC 1280 与移动 390 双端：4 张卡片 400px/364px 满宽、空态不再侵入编辑器。**修复已具备，只待 PR 合并部署。**

### ② 结构审计脚本 `scripts/structure-audit.cjs`（新增，`npm run audit`）

- 背景：v0.0.11 交付时“横向溢出/元素存在”检测全绿，却没抓住这个结构病——容器内部挤压不改变文档总宽，溢出检测恒为绿。v0.0.11 工作台核验只断言了“编辑器头部为直接子级”，但当时测的是**已修复的本地构建**而非线上部署版本，线上 v0.0.10 一直带病运行。这是检测流程的真实遗漏，本轮修正。
- 审计内容（全部为静态解析，无浏览器依赖，秒级完成）：模板区（`#app` 到 `</body>`，剥 script 与注释）标签严格栈平衡（跨层闭合/多余闭合/EOF 残留任一即 FAIL）；全部 `v-else`/`v-else-if` 与前一兄弟的 `v-if`/`v-else-if` 配对（img 等 void 标签计入兄弟）；`moyun-character-editor-head` 锚点闭合平衡与同层级检查（事故点专项）；`transition`/`transition-group`/`template` 开闭计数一致。
- 负样本验证：对 v0.0.10 基线源运行审计，准确抓出 3 项 FAIL（跨层闭合吞掉 editor-head 的 div、v-else 空态配对失败、editor-head 6 开 5 闭）；对当前源运行全部 PASS（标签平衡 0 问题、154 处 v-else 配对全对、Vue 容器标签开闭一致）。
- 接入流程：`npm run regress` 现在串联执行 regression-check + structure-audit；新增 `npm run audit` 可单独执行。

### ② 台词示例整句识别

- 根因：`normalizeStringList` 原来对任何列表字段都用同一套 `/[、,，\n]+/` 切分，台词里的顿号、逗号被当成标签分隔符——“你以为，你真的逃得掉吗？”被拆成“你以为”“你真的逃得掉吗”等碎行填入台词示例。
- 修复：函数增加第三参数 `mode`。`tags`（默认）保持原顿号/逗号拆分，供性格标签等短词字段使用；`dialogues` 模式只按换行分条，条内多句再按句末标点（。！？!?…）拆成完整句子，逗号/顿号永不拆句。四处台词相关调用（AI 生成载荷归一化 ×2、工作台草稿构建 ×1、草稿应用 ×1）均改为 `dialogues` 模式，其余列表字段不受影响。

### ⑦ 百万字级大书序列化瘦身

- 根因：每次自动保存对全书做两轮完整深拷贝（`syncBookData` 一份进 books、`buildLibrarySnapshot` 再一份进快照），随后 `JSON.stringify` 又序列化一次——百万字书每次防抖保存瞬时多占约 3 倍内存，Chrome 反复保存后内存峰值飙升可致崩溃。
- 修复：新增 `snapshotForSerialize`（浅结构展开 + 叶子值引用共享，层级超过 12 的极端结构回退 JSON 深拷贝）替代快照构建里的 `deepClone`。快照的三个消费方都只做 `JSON.stringify` 或只读（IndexedDB 写入、beforeunload 兜底、应急备份），序列化结果与深拷贝值层面完全一致，故引用共享安全；`syncBookData` 仍走 `deepClone`，跨书隔离不变。
- 运行时数据只存在一份，保存路径不再产生双倍大对象拷贝。

## 版本与回滚规则

1. 每轮修改前从上一稳定版本创建临时分支。
2. 版本号只提升最后一位，例如 `v0.0.7 → v0.0.8`。
3. 修改源码优先于生成产物；运行 `npm run build` 同步 `index.html`、`assets/css/moyun.css` 和 `assets/js/moyun.js`。
4. 完成构建、语法、差异和必要的浏览器/响应式测试后，才可将临时分支作为新稳定版本。
5. 回滚时优先切换到对应版本分支或提交，不使用破坏性重置覆盖用户数据。
